- Suite-honesty hardening (2026-08-26) — three drift families fixed across the specs above, all invisible to jsdom:
  - **Addendum-206 D2 drift**: `POST /admin/clusters` 400'd every UI-created cluster without an org ("An organisation is required for every cluster"), because the server made `clusters.organization_id` NOT NULL while the admin form still offered "— none —". `AdminClusters` form now requires the org select (native `required` + an inline guard for programmatic submits, jsdom-pinned), and `scenario.ts`'s provisioner plus `admin-audit-log.spec.ts`/`cluster-team-reorg.spec.ts` anchor every cluster (vendor clusters anchor to the agency org they serve). This was the root cause of `admin-reset.spec.ts`, `dashboard-tabs-rendering.spec.ts` and `admin-audit-log.spec.ts` failing with "cluster row never appears" — the earlier dismissal of admin-reset as environment-only was wrong.
  - **Optimistic-UI abort races**: custody batch actions (`request-custody__batch-*`), per-case custody actions, step/owner decision modals, and the asset create form all project state optimistically — a spec that asserted the projection and then navigated (login/logout) aborted the in-flight POST, silently undoing the action server-side. New `clickCustodyActionAndWait()` in `helpers/ui.ts` waits for the `POST /requests/:id/asset-custody/actions` response; batch clicks wait for the batch bar to unmount (it clears only on success); decision modals wait for modal close; the asset form waits for the create form to collapse. Admin-reset's "Confirm receipt" and the custody/remediation/happy-path specs now assert server-true states.
  - **Disclosure open-state drift**: `RequestDetailView`/`RequestDetailParts` render both the audit-timeline and credential-items disclosures `<details open>` (expanded by default, pinned by `RequestDetailView.coverage.test.tsx` and the demo suites) — but `happy-path.spec.ts` and `request-detail-elements.spec.ts` still clicked the summaries expecting a collapsed default, which closed the disclosure and hid the access-log links. The regression specs now pin `open` explicitly (with the toggle arms preserved) instead of fighting it.
  - **Approval-family decision race** (second pass): the dashboard action modals close OPTIMISTICALLY (addendum-196), so `rejection-flows`/`approver-edit`/`return-resubmit-full-approval`/`visibility-and-override` — whose decisions are rapid-fire queue-row confirms — were asserting modal-gone while the step-decision POST was still in flight; the next login's navigation aborted it (preflight logged, POST never arrived; downstream 409s from the single-slot idempotency token). `confirmDecisionAndWait()` (waits for the POST response) and `flushInFlightRequests()` (in-flight counter drained at the top of `login()`/`loginPasswordOnly()`) now pin server reconciliation; all five specs re-verified green. The clusters §H gate also pins the addendum-206 D2 required-org submit refusal in a real browser.
  - **Full-suite sweep hardening (2026-08-30)**: `admin-data` import/reset clicks are response-gated (reset route is `/admin/data/reset-seed`); `provisionRandomScenario` (owner-pending-count) anchors its clusters + org like `provisionActorsAndTeams`; `confirmDecisionAndWait` drains in-flight requests before returning so late responses cannot cross-resolve the wait and collide the single-slot idempotency token (the 409 cascade in approval-flood specs). Every regression spec except the LocalStack-gated `aws-localstack` and the post-suite `screenshot-count` self-check has been run green in the sandbox on this branch.
